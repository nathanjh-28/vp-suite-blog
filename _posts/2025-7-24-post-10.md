<!-- #### **What did you do last week?** -->
I refreshed my React skills and immersed myself in Material UI to work on building out a front end client application.  At first I dived in to a free dashboard template from Material UI and it was too complicated for me to use.  While working with Claude AI to make a minimal simple front end inspired by the dashboard and simple design elements, Claude asked if I would like for it to build a template for me.  This ended up being better than anything I could have made in a single day (the amount of time I gave myself for this) and I stepped in and modified where I needed to in this experimental react app.  I extended some of the components and layouts as well as modified the forms and data to match my api.  The next day I created a react project within my .NET core project and brought in the code from my experimental app.  I connected it to my api with a CORS policy and  implemented all the api calls needed to replace the mock data I used to implement the initial front end.

The great thing about this new front end is that it gives me a foundation to build the wireframes for the rest of the app by extending the layout and design logic already in place.

<!-- #### **Reflection on the process you used last week, how can you make the process work better?** -->
Material UI is a fantastic way to dive in to React without having to make a bunch of components.  On top of that, using tools like Claude AI have a way of speeding up development in ways that always shock and surprise me.  Combining Material UI and Claude were a winning combination to create a simple Minimum Viable Product front end in a very short amount of time.

I also found Claude using a similar pattern of bundling logic and calling it services.  It created a services folder and an api.jsx file to handle all my api calls so that in components you just say "getProjects()" and it's handled by the api service.  I really like this pattern for my api and seeing it also in the front end makes me like it even more.
